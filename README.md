# Rummy

这是一个纸牌 Rummy（拉米）玩法的**在线单机版**。

- 对局形式：固定 2 人，一方为玩家，另一方为机器人
- 完全静态的网页，无后端、无登录，可直接部署在 GitHub Pages 上
- 核心设计原则：**信息公平**——机器人不得读取牌堆内容，其决策所需信息与玩家完全一致

## 规则

### Rummy 基础规则

本作采用 **500 Rum**（又称 Pinochle Rummy）体系：亮出的组合**加分**，留在手里的牌**扣分**，先累计到 500 分者获胜。

#### 牌组与牌面分值

使用 1 副标准扑克 **54 张**（52 张 + 大王 + 小王）。

| 牌面 | 分值 |
| --- | --- |
| A | 15 |
| K / Q / J / 10 | 10 |
| 9 ~ 2 | 面值（9、8、7…2） |

> A 既可以作为最大牌（`Q-K-A`），也可以作为最小牌（`A-2-3`）；作为最小牌参与顺子时按 1 分计。

#### 万能牌（王牌 / Joker）

大王与小王均为**万能牌**，用于模拟任意一张牌。

**在手牌中**

- 按 **K 计，即 10 分**。百变牌鼓励尽早打出，长期握在手里会持续产生扣分成本。
- **不允许将王牌弃入弃牌堆**，只能通过「亮牌」或「接牌」打出。

**在组合中**

- 不能单独成组，必须依附于至少 2 张自然牌。
- 分值等于**被模拟的那张牌**的分值。
- 允许在接牌（lay off）时使用，但同样需要声明模拟目标。

**模拟目标的选择（由 UI 引导玩家）**

| 场景 | 可选目标 | 示例 |
| --- | --- | --- |
| 顺子中位置唯一确定 | 无需询问，自动推断 | ♠5 ♠6 ♠**8** + 王牌 → 只能是 ♠7 |
| 顺子中位置有歧义 | 弹出选择 | ♠7 ♠8 + 王牌 → 选 `♠6`（678）或 `♠9`（789） |
| 同点数组中花色未定 | 弹出选择花色 | ♠7 ♥7 + 王牌 → 选 ♣ 或 ♦ |

**视觉表现**

- 任何由王牌模拟出的牌，在其牌面上**绘制一圈异色边框**，以区别于自然牌。
- 边框需同时表明「这是模拟牌」以及它模拟的是哪张牌。

**关于「王牌换回自然牌」（joker replacement）**

这是 500 Rum 原始规则中的一项功能，具体表现是：桌面上已用王牌模拟的牌，其他玩家只要手中有对应的**自然牌**，就可以把那张自然牌打到该位置，并把王牌**收回自己手中**。

举例：桌面有 `♠5 ♠6 [王牌=♠7]`，你手里有自然牌 `♠7`，便可打出 `♠7` 替换掉王牌，然后把该王牌收入手中，继续用于其他组合。

这会带来两个问题：一是王牌可被反复回收利用，强烈放大王牌价值，与本作「王牌在手要扣 10 分」的成本设计相冲突；二是替换后原组合的模拟边界可能变化，判定逻辑复杂度显著上升。

**本版不实现此规则**，桌面上的模拟一旦成立即固定。

> 理由：王牌可回收会显著抬高玩家的决策成本与思考深度，且与本作「王牌在手即扣 10 分」的成本模型相互冲突。固定模拟可保持规则可预测，也便于 AI 评估局面。

#### 合法组合（Meld）

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 顺子（Run） | 同花色、点数连续，至少 3 张 | ♠5 ♠6 ♠7 |
| 同点数组（Set） | 点数相同、花色不同，3 ~ 4 张 | ♠8 ♥8 ♦8 |

- 同一组合内不允许出现重复的牌。
- 顺子长度上限为 13 张（`A-2-3 … Q-K-A`）。

#### 回合流程

每一回合按顺序执行：

1. **取牌**（二选一，必做）：
   - **摸新牌**：从牌堆顶摸 1 张。
   - **收弃牌**：从弃牌堆中取一张。分两种情况：
     - **取顶牌**：直接取走顶部一张，收入手牌。
     - **取历史牌（深层收取）**：可指定弃牌堆中**任意一张**非顶部的牌；指定牌必须在同一个动作中直接组成组合或接到桌面组合，绝不进入手牌。它上方的牌可与指定牌、原手牌一起组成该组合；参与组合的牌直接上桌，未参与组合的上方牌才进入手牌。若无法立即组成组合，则不能深层收取。
2. **亮牌 / 接牌**（可多次，可选）：
   - **亮牌**：从手牌亮出新的合法组合。
   - **接牌**（Lay off）：向桌面**任意**已亮出的组合追加 1 张牌，**包括对手的组合**。
3. **弃牌**：回合结束前必须向弃牌堆弃 1 张牌，弃牌后手牌数不变。
   - **例外**：若本回合已把手牌全部打出，则无需弃牌，回合直接结束（见 [一轮的结束](#一轮的结束)）。

**关于「取历史牌」**

这是本作的策略权衡点：用多加几张手牌的代价，换取一张当时就能用的牌。

- 强制连带收入是**核心约束**，正是它让这项操作不会变成无条件收益——弃牌堆越深的位置，连带代价越大，需要玩家自行判断是否值得。
- 连带收入的牌中若含王牌，照常按 10 分/张计入手牌（见 [万能牌](#万能牌王牌--joker)）。

> 牌堆摸完后，将弃牌堆（保留顶牌）洗回形成新牌堆；若两者同时耗尽，见 [边界情况](#边界情况)。

#### 首次亮牌

**无任何门槛**。玩家可在任意回合首次亮牌，组合分值不设下限。

> 原因：Rummy 大量局面下手中确实没有可出的牌，若再叠加门槛，会导致开局数回合双方都无法出牌，节奏停滞。

#### 一轮的结束

满足以下任一条件时，本轮立即结束并进入结算：

1. **出完手牌**：某一方把手牌全部亮出（含接牌）。此时**无需弃牌**。
2. **王牌卡死**：某一方手牌**只剩王牌**，且这些王牌无法再组成或接入任何合法组合（即无合法亮牌、无合法接牌、且规则禁止弃出王牌），则该方回合直接终止，本轮结束。
3. **无合法动作**：一方在回合内不存在任何合法操作（见 [边界情况](#边界情况)）。

#### 先手判定与轮转

**第一局第 1 轮**：从牌堆顶抽 1 张牌，只看**奇偶**（A/3/5/7/9/J/K 为奇，2/4/6/8/10/Q 为偶，按点数计），奇数由 **AI 先手**，偶数由**玩家先手**。

- 抽出的牌**放回牌堆顶**，不消耗、不改变牌堆顺序。
- 该牌在判定过程中**公开可见**，这是刻意设计：后手方得以看到牌堆顶一张牌，作为「后手补偿」——因为先手方本回合是从牌堆摸牌开始，而后手方开局就多知道一张信息。
- **抽到王牌时**（概率 2/54 ≈ 3.7%）：按大小直接映射奇偶，不重抽。
  - **小王 = 奇数 → AI 先手**
  - **大王 = 偶数 → 玩家先手**

**后续轮次**：每轮开始**交换先手方**（上一轮先手者本轮后手）。

> 王牌卡死属于「进一步限制囤牌导致的小概率事件」的兜底：不做特殊补偿，手中剩余的王牌**照常按 10 分计入扣分**，该方本轮得分因此可能为负。

### 积分

游戏分为「局」和「轮」的概念：每一局由多轮组成，每一局结算一次积分。

#### 一轮结算

```text
某方本轮得分 = 该方阵营桌面牌分值合计 − 该方手牌分值合计
```

- **分值按「阵营」而非按「出牌者」归属**：桌面上的组合归属于哪一方阵营，追加进该组合的牌就一并记给该阵营，无论这张牌是谁打出的。
- 因此**为对手的组合接牌时，接上去的牌的分值归对手**——这是「消耗自己手牌」所付出的代价。
- 结算只需按阵营对桌面牌求和，**不需要记录每张牌原本由谁打出**，简化了状态模型与实现。
- **出完手牌的一方手牌为 0**，故其本轮得分为其阵营桌面分合计，**不额外加分**。
- **未出完的一方**，其手牌分值从本轮得分中扣除，因此其本轮得分可以为负。
- 出完手牌**本身不提供任何额外奖励**，收益完全来自「避免扣掉自己剩余手牌的分」。

> 设计意图：既可以选择快速出完以锁定胜局，也可以选择保留高面值牌持续累加桌面分数，策略空间由玩家自行权衡。

#### 一局结算

- 每一轮的得分累加为本局得分（双方各自独立累计）。
- 当某一方本局得分**达到或超过 500** 时本局结束；由于结算发生在轮末，两人可能同时超过 500，属于正常现象。
- 本局结束时，得分高者获得本局胜利。
- **平局**（双方得分相等）：**加赛一轮**，可反复循环，直到分出胜负。

#### 结算与暂停流程

**轮末**：展示本轮比分对话框，玩家点击「确认」后才进入下一轮。

**局末**：展示本局结果，然后进入积分与段位结算页，玩家点击「开始新的一局」才发牌。

**未点击确认就关闭**：下次打开时**仍停留在同一个对话框**，对局进度不前进。

> 这是刻意的暂停设计：结算对话框是天然的存档点，玩家可以在两轮之间放心离开。同时也保证了 [存档机制](docs/技术方案.md) 不会读到「一轮已结束但下一轮未开始」的中间态——该状态无需持久化额外的中间数据，只需记录「待确认」标记。

#### 用户积分

用户（玩家）积分与单局得分是**两套独立数值**：

| 结果 | 用户积分变化 |
| --- | --- |
| 本局胜利 | +5 |
| 本局失败 | −3 |

用户积分用于段位计算与 **AI 强度映射**，跨局持久保存（`localStorage`）。

**对局状态同样持久化**：刷新或关闭页面后重新打开，将恢复同一牌局（同一发牌顺序、同一手牌、同一进度），可随时打断与放置。只有**手动认输**才结束本局并扣除 3 积分。设计意图是**防刷分而非强迫在线**——只要存档存在，重开必然回到同一局面，刷分路径即不存在。

积分是玩家的核心进度指标，**必须在界面上明确展示**：

- 首页与对战页均展示当前积分。
- 展示**距下一段位还差多少分**，例如「还差 32 分晋升 白银 III」，让玩家始终有明确目标。
- 段位阈值公开（见下节），因此无需隐藏积分；隐藏只会让玩家失去目标感。
- 钻石档位展示距**下一颗 ★** 的差额，高分段同样有可追逐的目标。
- 积分为负时（黑铁）进度条需支持负区间，不要以 0 为下界。

### 段位

段位根据用户累计积分计算，**每 50 积分一档**，向下取整：

```text
if 积分 < 0:   "黑铁"
elif 积分 < 500: 积分档位表[floor(积分 / 50)]
else:          "钻石" + "⭐️" × (floor(积分 / 50) − 10)
```

| 段位（中文） | 段位（英文） | 积分区间 |
| --- | --- | --- |
| 黑铁 | Iron | < 0 |
| 青铜 III | Bronze III | 0 – 49 |
| 青铜 II | Bronze II | 50 – 99 |
| 青铜 I | Bronze I | 100 – 149 |
| 白银 III | Silver III | 150 – 199 |
| 白银 II | Silver II | 200 – 249 |
| 白银 I | Silver I | 250 – 299 |
| 黄金 III | Gold III | 300 – 349 |
| 黄金 II | Gold II | 350 – 399 |
| 黄金 I | Gold I | 400 – 449 |
| 铂金 | Platinum | 450 – 499 |
| 钻石 | Diamond | 500 – 549 |
| 钻石 ⭐️ | Diamond ★ | 550 – 599 |
| 钻石 ⭐️⭐️ | Diamond ★★ | 600 – 649 |
| 钻石 ⭐️⭐️⭐️ | Diamond ★★★ | 650 – 699 |
| … | … | 每 50 分 +1 ⭐️ |

> 英文段位名沿用主流竞技游戏（如 LoL）的通用译法：`Iron / Bronze / Silver / Gold / Platinum / Diamond`，罗马数字保持 `III / II / I` 不变。星级在英文侧用 `★` 表示，避免与数字混排产生歧义。

- 积分为负时显示「黑铁」，不设降段保护。
- 钻石档位**不设上限**，星级随积分持续增加。

## 机器人 AI

**硬性约束：AI 与玩家使用完全相同的信息视图，禁止读取牌堆内容。**

AI 允许访问的信息**白名单**：

| 允许 | 说明 |
| --- | --- |
| 自己的手牌 | 完整内容 |
| 桌面所有已亮出的组合 | 含模拟牌的真实身份 |
| 弃牌堆全部内容 | 公开信息 |
| 牌堆**剩余张数** | 仅数量，不含内容 |
| 双方本局/本轮当前得分 | 公开信息 |
| 自己的历史操作记录 | — |

AI 禁止访问的信息**黑名单**：

| 禁止 | 说明 |
| --- | --- |
| 牌堆中牌的顺序与身份 | 核心约束 |
| 玩家的手牌 | — |
| 洗牌随机种子 / 随机数状态 | 否则可反推牌序 |

实现层面以**类型隔离**保证约束不被违反：AI 的入口函数只接受一个 `GameView` 快照对象，该对象在构造时即**不持有**牌堆数据；牌堆仅存在于 `GameState` 中，AI 模块不得引用 `GameState` 类型。这样即使后续 AI 逻辑变复杂，也无法「意外」看到牌堆。

AI 可基于公开信息做**概率推断**（例如统计已出现的牌来估算剩余牌分布），这属于合法策略，与读牌堆有本质区别。

## 交互约定

- **语言**：中 / 英双语，首页可切换，选择持久化。
- **灰遮罩**：手牌上的灰色半透明遮罩表示「此刻无法组成组合或接牌」，**仅作提示**，不代表不可操作。被遮罩的牌仍可被选中并弃出——弃牌是本回合的必做动作，若禁止选中会导致玩家无牌可弃而卡死。
- **王牌模拟选择**：当模拟目标存在歧义时，必须由用户显式选择，不可自动推断。
  - 顺子：在两端可行位置间选择（如 `678` / `789`）。
  - 同点数组：选择模拟的花色。
- **模拟牌标记**：所有由王牌模拟出的牌，牌面绘制**异色边框**。
- **接牌目标**：可选择桌面任意组合，需在视觉上明确标识该组合归属哪一方。
- **接牌代价提示**：向对手阵营接牌时，需提示「该牌分值将计入对手」，避免玩家误操作。

## 边界情况

### 王牌卡死（Joker Lock）

**触发条件**：某一方手牌仅剩王牌，且这些王牌**无法被消耗**——既不能与手牌组成新组合（手中已无自然牌可依附），也不能接入桌面任何已亮出组合，同时规则禁止弃出王牌。

**处理**：该方回合立即终止，**本轮结束并进入结算**，不视为「出完手牌」。

**计分**：不做任何特殊补偿，手中剩余王牌**照常按 10 分/张计入扣分**，该方本轮得分可能因此为负。

> 判定入口遵循「无合法动作」原则：若一方在回合内不存在任何合法操作（摸牌/收弃牌、亮牌、接牌、弃牌全不可行），即可直接判定卡死并结束本轮。由于禁弃王牌与「手牌仅剩王牌」同时成立时才可能触发，出现概率极低，不构成常规策略。

### 牌堆耗尽（不洗回）

**牌堆不做洗回**。牌堆摸空后若还需取牌，本轮立即结束并结算（类似炉石抽空卡堆），结算原因记为 `deckExhausted`。

- 弃牌堆**永不回洗**，因此牌只会单向流入弃牌堆，牌堆一定会在有限步内耗尽。
- 这也是本作的**收敛性保证**：若允许洗回，双方都不出牌时牌会在两堆之间无限循环，本轮永不结束。

> 弃牌堆在牌堆耗尽后仍可被「取历史牌」，但它只是消耗品，不再补充牌堆。

### 弃牌约束（防止来回搬运）

**本回合刚取到的牌，不能直接弃回弃牌堆。** 必须先从手牌中打出其他牌，才可弃之。

**为什么需要这条**：若不加限制，双方可以反复「取弃牌堆顶 → 原样弃回」，同一张牌在两人之间来回搬运，形成无限循环。这条约束切断了该循环。

- 次回合起，该牌即可正常弃出（约束仅限「取到它的那个回合」）。
- 王牌本就不可弃出，此约束对其无影响。
- UI 需对被禁弃的牌给出明确提示，避免玩家误以为卡死。

## 规则决策记录

以下为后续补充确认的规则，均已定档。

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 首次亮牌门槛 | **无门槛**。大量局面下手中无可出之牌，加门槛会导致开局停滞 |
| 2 | 出完手牌后是否弃牌 | **豁免**。手牌全部打出则直接结算，不走弃牌流程 |
| 3 | 弃牌堆取牌 | 顶牌直接取；**可取历史牌，但从该牌起其上所有牌收入手牌** |
| 4 | 先手与轮转 | 首轮抽牌判奇偶（奇=AI 先），牌放回堆顶；**小王=奇（AI 先）、大王=偶（玩家先）**；每轮交换先手 |
| 8 | 牌堆洗回 | **不洗回**，摸空即本轮结束（`deckExhausted`），同时作为收敛性保证 |
| 9 | 弃牌约束 | 本回合刚取到的牌**不可直接弃回**，防止同一张牌在双方之间来回搬运 |
| 5 | 轮末与局末 | 轮末弹比分框、局末弹结算页，**均需手动确认**；未确认则下次打开仍停在对话框 |
| 6 | 平局 | **加赛一轮**，可循环 |
| 7 | AI 思考节奏 | 先假装思考 **2 秒** |

### 王牌先手的裁定

**按大小映射奇偶**，不做重抽：

| 抽到 | 视作 | 先手方 |
| --- | --- | --- |
| 小王 | 奇数 | **AI** |
| 大王 | 偶数 | **玩家** |

- 保留「奇 = AI 先、偶 = 玩家先」的统一口径，王牌只是补上两个映射，不构成特例分支。
- 不重抽：避免为凑奇偶而反复放回重抽，逻辑更简单。
- 大小王恰好一奇一偶，两种结果各占一张，不会让某一方在王牌情形下获得系统性优势。
- 该牌判定后仍**放回牌堆顶**，与普通牌一致。

## 部署

项目目标为纯静态站点，可直接托管在 GitHub Pages：

1. 将构建产物（或源码根目录，视技术栈而定）推送到 `main` 分支；
2. 在仓库 `Settings → Pages` 中把 Source 指向对应分支与目录；
3. 等待 Actions 构建完成，通过 `https://<用户名>.github.io/<仓库名>/` 访问。

> 仓库已包含 [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)：
> 构建时通过 `VITE_BASE=/<仓库名>/` 注入子路径，`base` 无需写死在配置里，
> 因此本地开发始终走根路径 `/`，不受部署路径影响。
>
> 若使用自定义域名（部署在根路径），把该工作流里的 `VITE_BASE` 设为 `/` 即可。
